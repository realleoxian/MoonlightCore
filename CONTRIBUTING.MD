# Contribution Guidelines
If you read this i suppose you want to contribute to this mod. Well, you need to read the next guidelines if you want to:

Also by contributing to this mod you will also appear in the credits list with a kind of tag of your contribution. Example: "ExampleGuy - ISSUES | FEATURE" and on the CONTRIBUTORS.txt file of the repo you will appear with a little more detailed of what was your contribution to MoonlightCore

### Submitting an Issue/Bug
When submitting an issue, i would be grateful if you could follow these few guidelines:
- First and foremost, please check you issue hasn't already been posted, you can check this searching some special word of the issue/bug in the issue page of this repository.
- Please be stick with the template for issues/bugs
- Have a good description of the error, something like "This is very annoying" isn't usefull for the issue description.

### Submitting a PR
When submitting a PR you need to follow the next guidelines:

1. You need to have a good description of what are you doing in the PR you are submitting.
2. Please comment what are you doing, make an understandable code so that can help me to verify what your code is doing
3. Try to use a formatting on code like mine, comments and all
   - UPPERCASE for constants. Example: "EXAMPLE_CONSTANT"
   - Lowercase for regular variables. Example: "exampleVariable"
   - Lowercase for methods. Example: 'exampleMethod()'
   - For classes use this: 'ExampleClass'

With all that clarified, you should be fine contributing with a PR

### Requesting a Feature
When requesting a feature please follow the next guidelines:

1. First and foremost, be stick with the request feature template
2. Check if your feature isn't already request and if it is approved or not
3. Have a good description of your feature so it can be added more easily
4. And have some good reasons of why your feature should be added to MoonlightCore
